# Отчет по инструментам приемной комиссии

Добавлены 5 инструмента для агента приемной комиссии:

1. Получение актуальных цен на обучение.
2. Получение актуальных проходных баллов.
3. Получение списка необходимых документов по уровню обучения.
4. Получение контактной информации приемной комиссии.
5. Получение сроков обучения.

## Где хранятся данные

Основной структурированный источник:

- `AcademicQuestionBot/backend/data/admission_info.json`

Этот файл читается инструментами напрямую при каждом запросе. Это значит:

- после обновления JSON не нужно менять код;
- в большинстве случаев не нужен рестарт приложения, если процесс читает файл заново на каждый запрос;
- один файл является единой точкой обновления данных для приемной комиссии.

## Какие поля нужно заполнять

### Контакты

Блок `contacts`:

- `department` — название подразделения;
- `phone` — массив телефонов;
- `email` — массив email-адресов;
- `address` — адрес;
- `working_hours` — часы работы;
- `website` — ссылка на страницу приемной комиссии;
- `updated_at` — дата обновления информации.

### Документы

Блок `documents`:

- `bachelor`
- `master`
- `doctorate`

Для каждого уровня:

- `title` — заголовок;
- `items` — список обязательных документов;
- `updated_at` — дата обновления.

### Программы

Блок `programs` содержит список образовательных программ. Для каждой программы нужно заполнить:

- `name` — официальное название программы;
- `aliases` — варианты написания, по которым бот сможет находить программу;
- `level` — `bachelor`, `master` или `doctorate`;
- `duration` — срок обучения;
- `tuition.amount` — стоимость;
- `tuition.period` — период оплаты, например `за 1 учебный год`;
- `tuition.updated_at` — дата обновления стоимости;
- `passing_score.grant` — проходной балл на грант;
- `passing_score.paid` — проходной балл на платное;
- `passing_score.exam` — тип экзамена или основания;
- `passing_score.updated_at` — дата обновления баллов.

## Как загрузить правильную информацию

### Вариант 1. Ручное обновление основного JSON

1. Открыть файл `AcademicQuestionBot/backend/data/admission_info.json`.
2. Заменить тестовые значения на официальные данные приемной комиссии.
3. Проверить даты в полях `updated_at` и `last_updated`.
4. Запустить проверку:

```powershell
python scripts/validate_admission_data.py
```

5. Если проверка успешна, инструменты начнут использовать новые данные.

### Вариант 2. Использовать отдельный production-файл

Если не хотите хранить рабочие данные в стандартном файле репозитория, можно указать путь через переменную окружения:

```env
ADMISSION_DATA_PATH=C:\path\to\production\admission_info.json
```

Тогда все admission-инструменты будут читать именно этот файл.

## Откуда брать правильную информацию

Рекомендуемый порядок источников:

1. Официальная таблица приемной комиссии по стоимости обучения.
2. Официальные данные по проходным баллам на текущий год.
3. Утвержденный перечень документов для каждого уровня обучения.
4. Официальные контакты приемной комиссии с сайта или внутреннего регламента.
5. Утвержденные сроки обучения по образовательным программам.

Если данные приходят из Excel, Word или PDF, их лучше сначала привести к единой табличной форме, затем перенести в `admission_info.json`.

## Что уже реализовано в коде

- `backend/langchain/tools/admission_info.py` — инструменты и загрузка данных;
- `backend/agents/admission.py` — агент приемной комиссии, который выбирает нужный инструмент по запросу пользователя;
- `scripts/validate_admission_data.py` — проверка корректности JSON.

## Важно

Сейчас в `admission_info.json` лежат шаблонные значения для примера структуры. Перед использованием в продакшене их нужно заменить на реальные данные университета.
